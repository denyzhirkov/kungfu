Эпик 2 must-have плана (g5hhq6), v2.5.13. Закрывает петлю редактирования: после любого retrieval агент делал Read, чтобы получить точный код для Edit — теперь один вызов даёт всё.

НОВЫЙ USE CASE: KungfuService::edit_context(name, scope) в crates/kungfu-core/src/edit.rs (новый файл по конвенции mem_0003). Возвращает JSON:
- code: ПОЛНОЕ verbatim тело символа, НИКОГДА не усекается — пригодно как old_string для Edit напрямую (проверено: побайтово равно срезу файла). Стоимость декларируется через line_count вместо усечения.
- span{start_line,end_line}, symbol{name,kind,path,language,exported,doc_summary}
- neighbors: сигнатуры соседей по файлу (cap 30 + neighbors_total — честная декларация)
- callees / callers (cap 10) / callers_count из Calls-графа; call_graph: "indexed"|"not_indexed" (честная деградация для языков без графа)
- rationale: code-memories по symbol_id или пересечению line_range со span (cap 5)
- stale span (файл короче span) → bail с подсказкой reindex.

ОТЛИЧИЕ ОТ explore_symbol: тот даёт snippet(30 строк) для понимания; edit_context — полный текст + контракты вокруг, оптимизирован под последующую правку.

SCOPE-ДИЗАМБИГУАЦИЯ: scope фильтрует кандидатов ДО выбора (4 одноимённых ask_context разрешаются префиксом crates/kungfu-cli vs kungfu-core). Выбор кандидата вынесен в pub(crate) explore::pick_best_definition (общий с explore_symbol — одинаковый резолв имени).

MCP: тул edit_context (EditContextParam{name,scope}), handler в tools/context.rs. ВАЖНО: scope включён в ключ кэша вручную (format "name|scope"), в cached_scoped передаётся scope=None — иначе generic apply_scope post-filter порезал бы объект по path-полям, а scope здесь влияет на ВЫБОР символа, не на фильтрацию результата.

CLI: kungfu edit-context <name> [--scope prefix] — human-рендер печатает тело полностью (это суть тула).

ДОГФУДИНГ-НАХОДКА: callee "entry" (HashMap::entry) прилипал к единственному индексированному fn entry — добавлен в is_ubiquitous_callable стоп-лист.
