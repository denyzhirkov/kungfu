ИСТОРИЯ: до 2026-10-08 ensure_fresh_index сравнивал mtime fingerprints.json только с корневыми маркерами и 20 записями верхнего уровня src/crates/… → вложенные правки без edit-хука не детектились (найдено ревью 6qk252).

СЕЙЧАС (задача 2a6naz / 3dewoc, merge e45b4ab): crates/kungfu-core/src/freshness.rs. Опорное время = НАЧАЛО скана (TreeState.scanned_at в сайдкаре .kungfu/index/tree_state.json), сравнение `>=`. Stale если: корневые маркеры; любой индексированный файл отсутствует/новее; любой каталог из TreeState.dirs (все обойдённые сканером, включая пустые) новее И его shallow-листинг (scanner::scan_dirs_shallow — те же правила gitignore/hidden/ignore.paths/языков, что у полного скана) содержит неизвестную индексу запись. index_only (хук/MCP reindex) пишет per-path времена только для перечитанных файлов и тронутых каталогов — не сдвигает опорное время, чтобы не прятать правки без хука. Сканер всегда пропускает каталоги .kungfu на любой глубине. Замеры: deno 11k файлов — 9.4ms на вызов; этот репо ~0.2ms. Отсутствующий/битый сайдкар → один рескан.

ОСТАТОЧНЫЕ ПРЕДЕЛЫ: mtime в прошлом (cp -p, tar x, touch -t назад) не детектится; будущие mtime подхватываются, когда часы их догонят; ФС с секундной гранулярностью могут пропустить правку в ту же секунду, что старт скана. Каталог, изменённый только скрытыми/игнорируемыми файлами, перелистывается на каждом вызове до следующего скана (~2ms на deno).
