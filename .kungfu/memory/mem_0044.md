Branch config-symbols. Config file CONTENT is indexed as symbols (SymbolKind::ConfigBlock / ConfigKey, Language::is_config, Language::from_path for extension-less files). Formats: JSON, YAML, TOML, XML via tree-sitter; HCL/Terraform, CSV/TSV, .env, INI/.properties/.cfg, Dockerfile, Makefile via hand-written line scanners. INDEX_SCHEMA_VERSION 6 -> 7 (migration = reindex).

WHY HCL IS HAND-WRITTEN: tree-sitter-hcl 1.1.0 is ABI 15, tree-sitter 0.24.7 loads 13-14 (set_language -> LanguageError{version:15}). Upgrading tree-sitter workspace-wide was out of scope. Terraform names follow addresses: aws_s3_bucket.logs, var.x, module.x, data.T.N, output.x; labeled nested blocks keep labels (dynamic.ingress).

CONTRACT: every format module emits only through ConfigSymbols::push(parent, key, kind, ConfigValue, span) (crates/kungfu-parse/src/config_symbols.rs module doc). 2 levels, dotted names. ConfigValue::{None, Scalar, Block{count,noun}, List{count,noun}} - non-scalars carry no source text by construction. Ids assigned in finish(), #2/#3 suffix on repeats.

CAP: [index] max_config_symbols_per_file = 50, LEVEL-1 FIRST then level-2 in document order. The original pre-order cap lost whole Terraform resources on a real repo (main.tf 25 blocks, 10 indexed) - found only by running on a real project, not by tests or review. Trim recorded in FileEntry.config_symbols_total; partial parse in FileEntry.config_parse_errors (syntax error, guard, timeout, scanner mark_incomplete). Lock/state files by name only (is_lock_or_state_file). Keys > 256 bytes refused.

SECRETS: redaction is centralised in push - by any dotted-name segment (password, token, secret, *key, *pass, creds, ...) and by value shape (AKIA/ghp_/sk-/xox, -----BEGIN, long base64/hex, user:pass@ URL, password=/--token params, Authorization: Bearer). .env values and Dockerfile ENV/ARG values are never passed. BEST-EFFORT DENYLIST, not a guarantee; a secret used as a key name is not redacted. Protects the persisted index and embeddings; snippets are read from the file at query time as for code.

PARSER GUARDS (crates/kungfu-parse/src/lib.rs parse_config) - third-party grammars can kill the process: tree-sitter-yaml ABORTS (assert length <= 1024 in ts_parser__external_scanner_serialize) at 254 indent-stack entries, up to 2 entries per column, and it treats a lone \r as a newline. Guard: lines whose leading run exceeds MAX_YAML_BLOCK_INDENT = 60 are blanked (terminators kept) before parsing - file keeps its level-1/2 symbols (Kubernetes CRDs). tree-sitter-xml degrades past ~508 nesting levels: MAX_XML_DEPTH = 400 pre-scan. CONFIG_PARSE_TIMEOUT_MICROS = 5 s is a per-file last resort. Probe an aborting grammar only in a child process.

RANKING (crates/kungfu-search/src/config_rank.rs): CONFIG_PENALTY = 0.6, one decision point ConfigRanking::penalizes. Lifted when the query names a format/file or the project is config-heavy (Yaml+Hcl+Env+Dockerfile > 50% of those + code; Toml/Ini/Makefile/Json/Csv/Xml and test paths count on neither side). Config on test paths is ALWAYS penalised. One exact-name config match is spared when no code symbol has that name. INVARIANT: code-vs-code order and scores must equal a project without config - df statistics come from code symbols whenever any code symbol matches; the penalty is applied before every top-k cut (ask.rs strategies, EmbeddingStore::top_k_weighted); verify by old-vs-new binary comparison on a code-only project. Config value text does not score as a name; ties: code before config, blocks before keys. explore_symbol/edit_context resolve names unpenalised. Notes: RetrievalInfo.config_ranking {status, factor, hint}.

CONTRACT CHANGE: MCP find_symbol/find_files always return {results, config_ranking?}; CLI --json stays a bare array, note on stderr.

PROCESS LESSON: three implementers in one working tree (disk too full for worktrees) worked because file sets were disjoint, but rustfmt on a file follows its mod declarations and reformats other agents' files - format via stdin. Follow-ups: tsk 3ghc90.
