Эпик 5 must-have плана (o0kgat), v2.5.16. Один вызов после серии правок вместо «вспомни про affected, потом smart_test».

НОВЫЙ USE CASE: KungfuService::verify_change(depth) в crates/kungfu-core/src/verify.rs (новый файл по конвенции). Композит над существующими: diff_changed_lines → changed_symbols (пересечение span с хунками) → touched_contracts (exported среди изменённых — «ты поменял публичный контракт») + affected_staged(depth) (blast radius, merge по именам) + smart_test() (минимальный набор тестов). Пустой дифф → status:"clean". Cap 20 affected-записей с note (честная декларация) + hint на полный affected(staged=true).

PROVENANCE: поле call_graph: "indexed"|"imports_only" + note, что без Calls-графа радиус — файловая аппроксимация по импортам. (NB: affected_staged/smart_test, несмотря на "staged" в имени, работают по diff_changed_lines = working tree vs HEAD.)

MCP: тул verify_change{depth?=3} в tools/review.rs, БЕЗ кэша (зависит от состояния диффа, как smart_test/review), с record_served. CLI: kungfu verify-change [--depth]. README: строка в таблице тулов + правило агента «после серии правок зови verify_change перед объявлением работы законченной».

ПРОВЕРЕНО live на реальном незакоммиченном диффе самого эпика: 9 символов в 6 файлах, risk MEDIUM, публичные контракты (smart_test, review, EditContextParam), 8 affected (mcp tools через imports), осмысленный список тестов.

ИЗВЕСТНЫЙ ШУМ (pre-existing, не вносился): smart_test предлагает production-функции с "test" в имени (smart_test, test_subjects CLI-обёртки) как «тесты» — это эвристика is_test_symbol по имени. Не блокер; чистится в рамках будущей доработки smart_test.
