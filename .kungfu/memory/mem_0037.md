Под актуальный Claude Code (MCP-тулы deferred по умолчанию; на старте модель видит имена тулов + server instructions, лимит 2048 символов) правила доставляются ОДНИМ каналом:
- templates::MCP_INSTRUCTIONS (таблица маршрутизации, ~1918 симв., тест ≤2048) отдаётся в initialize.instructions (kungfu-mcp get_info; kungfu-mcp теперь зависит от kungfu-project). Плюс: правила появляются только когда сервер реально поднялся и работают в любом MCP-клиенте.
- Плагин больше НЕ инжектит правила SessionStart-хуком (plugin/rules/ удалён; SessionStart = только update-check). Тест plugin_session_start_does_not_inject_rules.
- CLAUDE.md-блок init (RULES_VERSION v2) — 3-строчный указатель на инструкции сервера (решение пользователя: страховка для клиентов, слабо воспринимающих instructions). v1 заменяется на месте, doctor предупреждает.
- Формулировка про свежесть обязана быть верной БЕЗ хука (см. mem_0035: ensure_fresh_index поверхностный): «с хуком Edit/Write переиндексируются сами, иначе reindex; после shell/codegen/git checkout — всегда reindex».

Edit-хук: REINDEX_HOOK_COMMAND = `kungfu index --from-hook` (читает JSON хука со stdin, корень = ближайший предок ФАЙЛА с .kungfu/, всегда exit 0, ни байта в stdout/stderr), матчер `Edit|Write` (MultiEdit нет в Claude Code; .ipynb не индексируются). jq больше не нужен. Миграция: init/doctor --fix заменяют ТОЛЬКО точную старую jq-команду (LEGACY_REINDEX_HOOK_COMMAND); кастомные хуки с `kungfu index --only` не трогаются (Info), но если старый шаблон был — новый ставится всегда, даже рядом с кастомным (кастомный может не срабатывать на Edit/Write). Нормализация путей (canonicalize, отказ вне корня/`..`, '/'-разделители) — в KungfuService::index_paths, общая для MCP reindex / --only / хука; плохой путь = ошибка всего вызова «nothing was reindexed».
