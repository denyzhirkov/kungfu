v2.7.0 добавил самообновление. Крейт kungfu-update (version/cache/github/apply) + CLI `kungfu update [--check|--to X.Y.Z|--quiet]`.

АРХИТЕКТУРА И ПРИЧИНЫ РЕШЕНИЙ:
1. Подмена бинаря = скачать ассет во временный файл В ТУ ЖЕ директорию, что и canonicalize(current_exe()), и fs::rename поверх. canonicalize обязателен: install.sh кладёт реальный файл в ~/.local/bin/kungfu и симлинкует /usr/local/bin/kungfu — без резолва симлинк был бы затёрт обычным файлом. Rename в одной директории атомарен; на Unix запущенный `kungfu mcp` держит старый инод и не падает, НО продолжает исполнять старый код → каждый success-путь печатает «перезапусти сессию» (это ровно скью из mem_0023).
2. Windows не даёт перезаписать запущенный .exe: старый переименовывается в kungfu.exe.old, при неудаче второго rename откатывается назад; .old подчищается при следующем apply.
3. Верификация ДО подмены: SHA256SUMS (новый шаг в .github/workflows/release.yml; релизы до 2.7.0 его не имеют → честный статус checksum: unavailable) + прогон скачанного бинаря с --version (ловит чужую архитектуру и HTML от прокси — то, что чек-сумма не ловит). TmpGuard удаляет частичную закачку на любом раннем возврате.
4. Проверка версии НИКОГДА не в request-path (инвариант mem_0008): kungfu-update::spawn_background_check с process-global UPDATE_JOB_RUNNING вызывается один раз из run_stdio_server; тул-хендлеры и CLI-эпилог читают только кэш ~/.cache/kungfu/update-check.json (TTL 24ч, шарится между проектами как модели). Нотис показывается не чаще раза в 6ч (notified_at в том же файле).
5. Сеть — единственная в kungfu, поэтому выключаема из одного места: kungfu-config::UpdateConfig {check, auto} + UpdateConfig::effective() (единственное место чтения KUNGFU_NO_UPDATE_CHECK / KUNGFU_AUTO_UPDATE; NO_UPDATE_CHECK абсолютен). auto=false по умолчанию — автоподмена под живым MCP даёт скью версий. Любая сетевая ошибка = тишина + debug-лог, никогда не ненулевой код возврата чужой команды.
6. Честность (инвариант retrieval honesty): UpdateStatus.source = network|cache|never_checked|disabled — «нет обновлений» из протухшего кэша отличимо от проверенного. Поле видно в project_status, `kungfu doctor` (кэш-онли, doctor остаётся офлайн-безопасным) и в --json.

ГДЕ ПОКАЗЫВАЕТСЯ: stderr-строка после успешной CLI-команды (кроме mcp/watch/update и --json), doctor, project_status.update, SessionStart-хук плагина (templates::UPDATE_CHECK_HOOK_COMMAND, парити-тест в plugin_sync.rs).

ПРОВЕРЕНО live: ./kungfu update --to 2.6.2 во временной копии скачал реальный релиз, прогнал смоук, подменил файл (2.7.0 → 2.6.2); --check --json вернул source=network; disabled/quiet/rate-limit пути проверены руками.

ГОТЧА НА БУДУЩЕЕ: смоук-тест сверяет вывод `--version` с ожидаемой версией, поэтому ассет в релизе обязан соответствовать тегу; если когда-нибудь начнём публиковать ассеты без bump'а workspace-версии, update будет честно отказываться ставить их.
