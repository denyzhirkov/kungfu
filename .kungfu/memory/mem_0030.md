DECISION (2026-07-08, design discussion): add per-file "purpose" and a glossary layer — but generative LLM summarization at index time is REJECTED: kungfu's contract is offline, deterministic, fast incremental indexing (6-12x is a benchmarked selling point), and bge-small is encoder-only. Layered approach instead, in priority order:

1. EXTRACTIVE purpose: FileEntry.purpose from module-level doc comments (Rust //!, Python module docstring, JS file header) via first_sentence(). Honest source (author-written). Feed into repo_outline/onboard and a file-level embedding text (pipeline precedent: symbol_embed_text = name+signature+doc_summary). Schema bump + reindex migration (mechanism exists since v2, schema_version.json).

2. HEURISTIC tags: structural classification from signals already in the index — path/name conventions, resolved import Relations (sqlx→database, axum::Router→routing), symbol-kind distribution. Lands in the existing FileEntry.tags field. Constraints: only high-precision conservative rules; NO closed taxonomy enum (free-form tags); mandatory provenance (purpose_source: doc|heuristic) per the retrieval-honesty invariant — a confident wrong label is worse than none; authored doc beats heuristic on conflict.

3. AGENT ANNOTATIONS: new MCP tool annotate_file (memory_add pattern) — the agent generates purpose/glossary text, kungfu stores and serves. This gets LLM-quality without an LLM dependency in the engine: kungfu = deterministic retrieval, agent = intelligence. Also the ONLY viable path for business-jargon→symbol glossary mapping (not extractable deterministically).

4. DETERMINISTIC glossary (lowest value, last): distinctive terms from identifier splitting minus a generic-programming stoplist (stoplist.rs pattern) → definition site → doc_summary of same-named type. Serve inside onboard/repo_outline output, not a separate store. Note: find_symbol + semantic_search already cover most of this scenario.
