MCP stdio uses stdout as the JSON-RPC protocol channel. `tracing_subscriber::fmt()` defaults its writer to STDOUT, so any log event (even a single `warn` under the default `EnvFilter::new("warn")`) corrupts the framing and the client (Claude Code) hangs forever on ALL subsequent tool calls — no timeout, just an infinite spinner. Manifested with newer Claude Code clients (2.1.x) which are stricter about stdout framing than older ones; kungfu code itself was unchanged. Fix: add `.with_writer(std::io::stderr)` to the subscriber builder in crates/kungfu-cli/src/main.rs (the single shared logger init used by all subcommands incl. `kungfu mcp`). Verify with: `RUST_LOG=info kungfu mcp` piped a JSON-RPC handshake — stdout must be pure JSON, the `starting kungfu MCP server` INFO line must appear on stderr. Regression guard: never let tracing/println go to stdout from the mcp path.
