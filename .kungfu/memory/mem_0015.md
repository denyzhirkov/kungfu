Эпик 1 must-have плана (udgt6w) + попутный acidtn. v2.5.12.

1. KungfuService::index_paths(paths) (kungfu-core/src/lib.rs) — обёртка над Indexer::index_only с нормализацией путей (абсолютные под root → относительные, strip "./"). Пустой paths → bail с подсказкой.

2. MCP-тул reindex (params.rs: ReindexParam{paths}, tools/project.rs: reindex, делегат в lib.rs). ВАЖНО: использует mcp.service_untracked(), НЕ service() — иначе ensure_fresh_index запустил бы свой incremental скан до целевого реиндекса, обессмыслив его. После реиндекса cache.clear(). Семантика: агент после Edit/Write зовёт reindex со своими путями; lazy ensure_fresh_index остаётся safety-net для внешних изменений (git pull, форматтеры). После reindex fingerprints.json обновлён → mtime-проверка ensure_fresh_index видит индекс свежим, повторного скана нет.

3. CLI: kungfu index --only <PATH>... (main.rs num_args=1.., commands.rs index). Нужен harness-hook'ам (hook зовёт CLI, не MCP). Скорость на живом тесте: 8мс на файл.

4. Harness hook задокументирован в README (раздел "Auto-reindex on edit"): PostToolUse matcher Edit|Write|MultiEdit|NotebookEdit → jq .tool_input.file_path | xargs kungfu index --only. Пользователь подключает сам в .claude/settings.json.

5. Фикс acidtn (тот же класс, что relations-wipe mem_0014): index_incremental теперь мёржит memories — старые записи неизменённых существующих файлов сохраняются (фильтр по changed_paths + current_paths), пересборка только для re-parsed. Изменённые doc-файлы re-parse явно через parse_md_file, т.к. scan_docs бежит только в index_full; охват зеркалит is_doc_memory_source (корневые *.md + docs/ doc/ adr/ decisions/). Тот же re-parse добавлен в index_only. Регресс-тесты: incremental_with_no_changes_preserves_memories, index_only_touches_just_the_given_file.

ПРОВЕРЕНО live: CLI-поток (edit b.rs → index --only b.rs 8ms → find-symbol видит новый символ, callers чужого файла целы) и MCP-поток по stdio (reindex → find_symbol видит). Нюанс MCP: сервер обрабатывает запросы конкурентно — если слать reindex и find_symbol одновременно без ожидания ответа, порядок не гарантирован; реальный агент ждёт результат тула, так что не проблема.
