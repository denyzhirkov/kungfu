A raids2 .kungfu/index/symbols.json reached 18GB: a 1.2KB config.ts appeared 450K+ times in the file — symbol DUPLICATION from a pre-2.5.x indexer (watcher storm without debounce/dedup), NOT a huge source file. Loading that 18GB JSON via ensure_fresh_index OOM-ed/hung the MCP server; every tool call on that project blocked. Not reproducible on 2.5.5 (clean reindex -> 132KB); fix for the legacy index was to delete it and reindex. Guard added in 2.5.5: kungfu-config [index] max_file_bytes (default 2 MiB); kungfu-index read_for_index skips oversized + binary files (NUL-byte sniff) and records them by NAME ONLY (still discoverable); both index_full and index_incremental route through it; kungfu-mcp runs the filesystem watcher ONLY when watch=true (previously unconditional, ignoring watch=false, causing background re-index storms). CAVEAT: the cap is byte-based and does NOT bound symbol-count explosions — a small file emitting huge symbol counts would slip past. A per-file symbol cap was considered and deliberately deferred because the duplication bug no longer reproduces; revisit if a sane-sized file ever blows up the index again.
