KungfuService больше не god-object. lib.rs — slim facade (206 LOC): структура + ctor + accessors + resolve_budget + ensure_fresh_index + status + index_full/incremental/changed + тонкие wrapper'ы для search + track_call/usage_stats + mod-декларации.

Use cases в отдельных файлах внутри crates/kungfu-core/src/:
- ask.rs (809 LOC) — ask_context*, grep_content, fill_snippets, StrategyWeights, keyword highlighting
- explore.rs (346) — repo_outline, file_outline, explore_symbol, explore_file, investigate, symbol_snippet
- review.rs (531) — hotspots, affected, smart_test, review, coupling + is_test_symbol helpers
- onboard.rs (294) — onboard + детекторы architecture/naming/test pattern
- history.rs (210) — file_history, symbol_history, change_timeline, diff_context
- memory.rs (127) — memory_add/list/show/search/update/archive/remove/pin/unpin
- search_ops.rs (168) — callers, callees, semantic_search, search_rationale
- helpers.rs (145) — pub(crate) detect_intent, is_stop_word, detect_primary_language, is_code_language, truncate_text + тесты
- types.rs (113) — все pub Info/Result структуры (StatusInfo, RepoOutline, ...)

Multiple `impl KungfuService` блоков в разных файлах — стандартный Rust паттерн, не требует traits. Поля `project`, `store` и accessors `store()`, `search()` стали `pub(crate)` для модулей. Контракты не менялись, MCP/CLI не правились. Build + 97/97 tests + clippy зелёные.

Конвенция: добавлять новый use case = новый файл с `impl KungfuService { ... }` блоком, регистрация модуля в lib.rs. Дробить, если файл переваливает за ~800 LOC и содержит >1 use case.
