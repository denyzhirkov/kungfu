Этап 3: убрана выдуманная метрика экономии в usage_stats (kungfu-mcp).

ПРОБЛЕМА: estimated_raw_bytes = cache.calls_served * 8192 (константа 8KB/вызов), compression_ratio делил выдуманное на реальные bytes_served → "8.3x" ни на чём не основано.

ЧЕСТНЫЙ BASELINE: CacheState.raw_bytes_baseline копит сумму on-disk размеров РЕАЛЬНЫХ файлов, на которые ссылается каждый выданный результат (то, что агент прочитал бы, открыв их). Механика в cache.rs: referenced_paths(result) рекурсивно собирает все строковые поля "path" из JSON-результата (дедуп через HashSet); load_file_sizes читает .kungfu/index/files.json → path→FileEntry.size; raw_baseline_bytes суммирует размеры. file_sizes мемоизируется в CacheState, сбрасывается в clear() (т.е. при реиндексе). usage_stats теперь: raw_bytes_baseline (реальный) vs bytes_served, compression_ratio, estimated_tokens_saved=(raw-served)/4, + поле baseline_method с пояснением методики. Path-less результаты (project_status) → baseline 0 (честно).

ПОЛНЫЙ УЧЁТ КОМАНД: раньше track_call звался только внутри cached_scoped → нетрекаемые read-тулы (project_status, repo_outline, file_outline, file_history, diff_context, debug_trace, hotspots, smart_test, review, memory_search/list/get) не попадали в per_command и в baseline. Введён единый KungfuMcp::record_served(tool, result) — обновляет calls_served/bytes_served/raw_bytes_baseline + персистентный track_call. cached_scoped теперь зовёт его (и на hit, и на miss); нетрекаемые тулы — тоже, в конце тела (let out=...; mcp.record_served(name,&out); Ok(out)). Чистые мутации (memory_add/update/archive, embeddings_build) НЕ трекаются как served — это не retrieval.

КОНВЕНЦИЯ (закрепляет этап 1): презентация/метрики — в адаптерах. record_served — единая точка учёта; новый MCP read-тул, не идущий через cached*, обязан вызвать record_served перед возвратом, иначе выпадет из usage_stats.

Unit-тесты: referenced_paths (дедуп + path-less/invalid → пусто) в cache.rs.
