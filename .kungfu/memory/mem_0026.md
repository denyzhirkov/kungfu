Сборка пакета в kungfu-rank заменена с чистого top-K на жадный marginal-relevance проход (select_diverse): эффективный скор кандидата = base × SAME_FILE_DECAY^n (n = уже выбрано из того же файла) × SAME_DIR_DECAY^m (m = выбрано из той же директории, но других файлов; та же директория того же файла НЕ штрафуется дважды). Константы: SAME_FILE_DECAY=0.5, SAME_DIR_DECAY=0.85, MAX_DIVERSITY_CANDIDATES=200 — pub const в kungfu-rank рядом с кодом сборки.

Почему мультипликативный, а не вычитающий: скоры стратегий разномасштабные (symbol match ~1.0, grep 0.45, vector 0.55) — вычитание убивало бы слабые стратегии; множитель scale-free и естественно сохраняет концентрированные ответы при большом отрыве (single-file lookup остаётся в одном файле — закреплено тестом concentrated_answer_still_dominates). item.score в пакете остаётся базовым — decay влияет только на отбор и порядок, не на честность скора.

Бенчмарк (50 кейсов, до/после на идентичном закоммиченном дереве): aggregate 46.41→48.96, passed 32→34, over-selection 19.60→33.84 (+14.2), cross-file +9.6, files_within_limit failures 12→9. refactor-prep −2.1 — целиком байтовый шум сниппетов (case-014: корректность 1/1 must + 2/2 should в обоих прогонах, только bytes 1939→3009). Свип констант (0.55/0.9 и 0.4/0.8) — поверхность плоская, дефолт лучший по балансу.

Gotcha воспроизводимости: recorded baseline 48.31 не воспроизводится точно — дрейф только на kungfu self-кейсах (состояние дерева/индекса/embeddings), внешние 40 кейсов на pinned-репо воспроизводятся бит-в-бит. Для честного A/B — оба прогона на одном закоммиченном дереве.

Проходит через kungfu-rank: ask_context, investigate (через ask_context), debug_trace, commit/pr/diff_context. Мимо kungfu-rank (свой отбор, диверсификация не применяется): explore_symbol, explore_file, edit_context, onboard, semantic_search.
