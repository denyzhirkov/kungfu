KungfuMcp больше не god-object. lib.rs (297 LOC) содержит только структуру + ctor + один #[tool_router] impl с тонкими делегатами (1-3 строки на тул) + ServerHandler + run_stdio_server.

Почему делегаты, а не multiple #[tool_router] блоков: rmcp макрос `#[tool_router]` генерирует одну `Self::tool_router()` функцию на impl. Несколько блоков с тем же макросом конфликтовали бы. Делегаты — единственный механизм-нейтральный способ дробления.

Структура crates/kungfu-mcp/src/:
- lib.rs (297) — struct + ctor + #[tool_router] impl (тонкие тулы)
- params.rs (149) — все param-структуры + parse_budget
- cache.rs (170) — CacheState, CACHE_CAPACITY, cache_key, impl KungfuMcp { service, validate_cache, cached, cached_scoped }
- scope.rs (65) — apply_scope post-filter
- tools/mod.rs (7) — реэкспорт групп
- tools/project.rs (66) — project_status, repo_outline, file_outline
- tools/search.rs (142) — find_symbol, get_symbol, search_text, find_files, semantic_search, find_related_symbols
- tools/context.rs (94) — ask_context, diff_context, explore_symbol, explore_file, investigate
- tools/graph.rs (52) — callers, callees
- tools/history.rs (32) — file_history, symbol_history, change_timeline
- tools/review.rs (100) — usage_stats, hotspots, onboard, affected, smart_test, review, coupling
- tools/memory.rs (92) — memory_add/search/list/get/update/archive

Каждый tool в tools/*.rs — pub(crate) free function вида `fn name(mcp: &KungfuMcp, params: XParam) -> Result<String, String>`. Доступ к кэшу/сервису — через `mcp.service()` и `mcp.cached*()`, которые подняты до `pub(crate)`. Поля `project_root` и `cache` тоже `pub(crate)`.

Конвенция: новый MCP-тул = добавить тело в соответствующий `tools/{group}.rs`, добавить тонкий делегат в #[tool_router] impl в lib.rs. Если групп нет подходящих — новый файл `tools/foo.rs` + регистрация в `tools/mod.rs`.
