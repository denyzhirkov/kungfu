ARCHITECTURE (v2.5.21): the manual/project memory layer is no longer a single project_memory.json array. It is now one Markdown file per entry under `.kungfu/memory/mem_NNNN.md` (TOML `+++` frontmatter = metadata, body = content) — the DURABLE SOURCE OF TRUTH, human-readable and git-diffable — plus a derived `.kungfu/memory/manifest.json` (metas + inverted index `term -> ids`) that is always rebuildable by scanning the `.md` files.

Code: `kungfu-storage::project_memory::ProjectMemoryStore`. `JsonStore` delegates `add/get/update/remove/archive/next_id` + new `list_project_memory_meta`, `project_memory_candidates`, `load_project_memory_bodies`. Manifest cached in RefCell; staleness detected by `.md` file count vs manifest len (rebuild on mismatch); writes atomic via [[mem_0022]] atomic_write. Migration from legacy json is one-time + non-destructive (old file -> project_memory.json.bak).

Hot paths are SELECTIVE (no full-corpus body reads): memory_search does index candidate-gen (token + prefix recall) then runs the UNCHANGED scorer on only those bodies; show/get read one file; list filters metadata then reads survivors; ask_context injection loads query ∪ pinned ∪ cross-ref candidates and clusters conflicts on metadata before reading cluster bodies. This replaces the old "load every entry on every ask_context" hot path.

This resolves the scaling concern flagged in [[mem_0022]] (that note now describes the superseded single-file design). Remaining documented escalation (YAGNI): manifest is still rewritten whole on each add (metadata + postings, NO bodies) — fine for years; only revisit with an append-log if manifest hits tens of MB. Search recall caveat: candidate-gen is token/stem/prefix based, not arbitrary substring — pathological mid-token substring queries that the old full scan caught may miss; final scoring on candidates is otherwise identical.

GOTCHA (how this entry was recovered): a stale MCP server binary (v2.5.17) running during the migration recreated a legacy project_memory.json and wrote new memory_add calls there (as mem_0001), invisible to the .md store. Until the installed `kungfu` binary is upgraded to >=2.5.21 and the MCP server restarted, MCP memory_* tools operate on a SEPARATE stale file — use the CLI for memory ops, or reinstall + restart first.
