Этап 1 ранжирования (v2.5.8). Три источника шума в retrieval, проверены на трёх репро-запросах:

1. PATH-MATCH FALLBACK. ask.rs file-level fallback инжектил символ с хардкод score=0.55 за совпадение по имени файла — это обгоняло реальные name-match (0.45). Заменено на tunable вес StrategyWeights::path_fallback_score (default 0.3, env KUNGFU_W_PATH_FALLBACK) — теперь backfill, а не вытеснение. Репро: ask-context "how does budget trimming work during context packet assembly" — топ занял ask_context (0.75), а не ProjectMemoryItem/investigate по слову "context" в пути.

2. ПОНИЖЕНИЕ ТЕСТОВ. is_test_symbol перенесён review.rs→helpers.rs (+тест туда же). Новый helpers::test_symbol_ids(symbols) — обходит parent_symbol_id вверх и ловит символы внутри module/class с именем "tests"/"test" (язык-независимо), union с эвристикой по имени/пути. Это ловит inline #[cfg(test)] mod tests с production-именами, которые старая эвристика по имени пропускала. Применение: (а) ask_context для intent Understand|Lookup умножает score теста на test_penalty (default 0.5, env KUNGFU_W_TEST_PENALTY); (б) semantic_search keyword-fallback путь умножает на 0.5 (vector-путь НЕ трогаем — косинус осмыслен). Репро: search --semantic "where do we skip binary files" — is_binary/scan_files/index_file (0.36) теперь выше тест-функции read_for_index_skips_... (была 0.54 сверху).

3. MEMORY_SEARCH ПОРОГ. Ниже FULL_CONTENT_THRESHOLD=0.45 возвращается стаб {id,kind,title,excerpt(160ch),hint→memory_get/show} вместо полного ~1KB content. Применено в ДВУХ адаптерах: kungfu-mcp/src/tools/memory.rs (excerpt helper) и kungfu-cli --json (truncate_str, hint "kungfu memory show <id>"). CLI non-json уже был компактен. Репро: memory search "budget trimming packet assembly" — mem_0003/mem_0004 (0.35) свернулись в стабы.

Конвенция: презентационная логика (пороги, компакция, excerpt) живёт в адаптерах (mcp/cli), не в core; core отдаёт scored-данные. Веса ранжирования — в StrategyWeights с env-override.
