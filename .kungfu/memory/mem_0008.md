MCP server "infinite hang" on tool calls had TWO independent root causes with the same symptom:

1. (Fixed b0ca282, 2.5.2) tracing_subscriber::fmt() defaulted its writer to stdout — the JSON-RPC channel. A single log line corrupted framing → client hung. Fix: .with_writer(std::io::stderr) in kungfu-cli/src/main.rs.

2. (Fixed 2.5.3) The candle/BERT embeddings patch (v2.3–2.5, "AI in search") ran heavyweight synchronous inference IN the MCP request path. Two compounding bugs:
   a) ask_context (ask.rs Strategy A2) and semantic_search (search_ops.rs) called open_default_engine() INSIDE every request → reloaded the 133MB bge-small model from disk and rebuilt BertModel on EVERY call. ask_context/investigate are the agent's default first call, so every primary kungfu call paid a full model load. Under repeated/stacked calls these loads accumulated in RSS → the 8GB wedged processes we saw.
   b) embeddings_build is minutes of CPU-bound inference run as a plain sync MCP handler — it blocked the rmcp stdio event loop.

Fix 2.5.3:
- kungfu-embed: added shared_engine() — process-global OnceLock<Box<dyn EmbedEngine>>; load the model once per process. ask.rs + search_ops.rs hot paths use it. embeddings_build/status keep open_default_engine() (rare/explicit, must reflect fresh install state).
- kungfu-mcp/src/lib.rs: embeddings_build is now async fn offloaded via tokio::task::spawn_blocking.
- kungfu-mcp/src/cache.rs: added service_untracked() (KungfuService::open without ensure_fresh_index); usage-stats track_call now uses it instead of a second full service() — was doing ensure_fresh_index (fs-stat scan + possible reindex) TWICE per tool call.

MEMORY GROWTH — RESOLVED, not a leak. Empirically verified (2026-06-06): forced full rebuild of all 859 symbols peaked at ~780MB RSS, receded to ~314MB, finished in ~52s. No unbounded growth inside a single build. The earlier 8GB was solely the per-call model-reload bug (2a), now fixed by shared_engine. The AI search is kept, not removed.

GOTCHA (still true): KungfuMcp::service() (cache.rs) rebuilds a fresh KungfuService on EVERY tool call via KungfuService::open(); any per-call caching MUST live at process scope (kungfu-embed static), not in KungfuService.

npm DISTRIBUTION REMOVED (2.5.3): deleted npm/ wrapper dir; plugin/.mcp.json now launches `kungfu mcp` from PATH instead of `npx kungfu-ai`. Published npm package `kungfu-ai` is stale 2.0.1 — still on the registry; needs manual `npm deprecate`/`npm unpublish` (owner decided not to maintain npm for now). build.sh still uses plain `cargo build --release` (no --features semantic); the install.sh-distributed binary is built semantic elsewhere — feature/installer wiring should be made explicit (still OPEN).
