kungfu-storage now has a process-global cache of PARSED index shards (crates/kungfu-storage/src/process_cache.rs), fixing the per-call re-parse caused by KungfuMcp::service() rebuilding KungfuService on every tool call (mem_0008 gotcha).

Design:
- Static Slot<T> per shard (files, symbols, relations, memories, fingerprints), each a RwLock holding AT MOST ONE Arc snapshot keyed by (path, stamp). Stamp = inode (unix) + mtime + len — atomic_write renames a fresh tmp file over the target, so any rewrite changes the inode; the O(1 stat) check happens on EVERY access ("fingerprint check on read is the safety net" invariant). No TTL, no background invalidation.
- Parse runs under the write lock (single flight); poisoned locks recovered via PoisonError::into_inner (no unwrap). save_* CLEARS the slot rather than publishing (publishing could wedge on a stat/rename race with another process); next reader re-parses once.
- JsonStore per-instance RefCell caches now hold Arc<Vec<T>> and pin the first-loaded snapshot for the instance's lifetime (consistent view per service call). load_* keep their Vec-by-value signatures (clone from Arc); NEW Arc accessors files_arc/symbols_arc/relations_arc/memories_arc return the shared snapshot with zero clone.
- SearchEngine::get_all_symbols/get_all_files now return Arc<Vec<_>> (signature change, all kungfu-core callers adjusted). Hot paths (callers/callees/has_call_graph, find_symbol, search_text, find_related, edit/verify/review/onboard/ask relation scans) use the Arc accessors. callers/callees also replaced the O(edges×symbols) `iter().find()` loop with a HashMap id→symbol + early break at top_k.

Measured (release, fresh service per call = MCP pattern): this repo callers cold 1.7ms → warm 63µs; synthetic 100k symbols + 1M call relations (131MB JSON) cold 220ms → warm 3.7ms.

GOTCHA for future work: anything that writes index shards MUST go through JsonStore::save_* (which clears the process slot) or rely on the stamp check — writing a shard file in place with identical length on a filesystem with coarse mtime AND same inode is the only theoretical stale window, and atomic_write makes it impossible in-repo. Parallel tests in one binary share the slots — kungfu-storage cache tests serialize on PROCESS_CACHE_TEST_LOCK; copy that pattern if adding tests that touch shards from multiple temp dirs.
