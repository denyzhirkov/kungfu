Было на deno (11k файлов/59k символов): index_only ≈4.4s, incremental (1 файл) ≈5.5–7.3s. Стало ≈0.27s / ≈0.6–0.7s. Основные потери: перенос символов неизменённых файлов O(files×symbols) (3.2s), config relations (0.9s), test relations (пары по стемам main/__test__).

КЛЮЧЕВОЕ: file id = хеш содержимого → каждая правка меняет id файла и всех его символов. crates/kungfu-index/src/delta.rs переносит рёбра (renamed_ids: старый id → единственный новый; None только если преемники реально различаются), пере-применяет правило «уникальное имя callee» для имён, у которых изменилось число определений, перепарсивает «осиротевших» импортёров (orphaned_importers: старый id без единственного преемника или разделённый набор идентичных копий) — один проход, без каскада. test/config relations пересобираются целиком (дёшево). Раньше: устаревшие рёбра, копящиеся self-edges, дубли test/config (relations.json 2.28→3.14MB за 6 правок).

Сайдкар .kungfu/index/calls_dropped.json — рёбра, отброшенные частотной отсечкой, чтобы targeted-прогон считал отсечку точно; пишется full-индексом всегда, targeted — только если уже существует; битый/oversized → удаляется (warn), I/O-ошибка → warn без удаления; отсутствует → старое поведение до следующего full.

Символы идентичных файлов: dedup по id ДО build_call_relations (общий символ = одно определение) и canonical_symbol_paths — путь = алфавитно первый живой путь (детерминированно в full и targeted). Следствие: verify_change/review по s.path == file не видят символы неканонической копии (известный предел).

Известные пробелы (документированы в delta.rs, провенанс callers/callees честно говорит «edges from files not re-parsed since the last full index may be missing — kungfu index --full»): имя стало уникальным → не перепарсенные файлы не получают новое ребро; import fallback не пере-резолвится, когда появляется лучший точный путь; same-file calls при cross_file_only=false. Страховка — tests/targeted_equivalence.rs (targeted == full как множества, по шардам).
